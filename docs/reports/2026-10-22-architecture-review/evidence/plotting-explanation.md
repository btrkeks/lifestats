Per the user clarification, image plots remain the main Obsidian frontend and a polished desktop-wallpaper legacy artifact. Retain them now; design their entire presentation path to be disposable. Future React Native frontends use native interactive charts. The proposal already says [rendering consumes canonical views](/home/daniel/.local/share/src/lifestats/docs/reports/2026-10-22-architecture-review/design.md:55); this needs three explicit ownership boundaries.

**Current code.** [`GetPlotData`](/home/daniel/.local/share/src/lifestats/core/application/src/use_cases/queries/get_plot_data/handler.rs:123) reads values, resolves goals, evaluates achievement, assigns RGB, converts drawable values, and calculates axis bounds. [`PlotData`](/home/daniel/.local/share/src/lifestats/core/plot-domain/src/plot/data.rs:126) carries title, plot type, points, and axis configuration. Despite its domain naming, it is a plot viewmodel. [`PlotRenderer`](/home/daniel/.local/share/src/lifestats/core/plot-domain/src/plot/renderer.rs:46) consumes it plus dimensions/label settings. The [timeline handler](/home/daniel/.local/share/src/lifestats/core/application/src/use_cases/queries/get_daily_timeline_plot/handler.rs:33) instead directly calls concrete plotting with 800×1500 dimensions.

**Proposed separation, not implemented:**

- **Product queries** expose authoritative daily/range/timeline data: dated typed values, declared units, normalized intervals and canonical totals, effective goals, and authoritative achievement. Preserve “no goal,” unknown goal history, zero versus missing observations, and unavailable achievement explicitly. Temporal goal resolution, interval aggregation/normalization, and achievement remain product responsibilities, independent of every chart. Today [duration aggregation depends on plot type](/home/daniel/.local/share/src/lifestats/core/application/src/services/plot_data_builder.rs:74), and [units can depend on Fitbit tags](/home/daniel/.local/share/src/lifestats/core/application/src/services/plot_data_builder.rs:14); those semantic responsibilities must survive removal of plotting. Neither `PlotType`, RGB, axis bounds, nor image dimensions belongs in the product query contract.
- **Plot presentation** maps product results into image-specific viewmodels. It owns chart selection, displayed titles/labels, achievement-to-color mapping, axis bounds, zoom, and layout. It chooses whether to display canonical intervals or totals; it never recalculates their meaning or achievement. Existing [`percentage_to_color`](/home/daniel/.local/share/src/lifestats/core/application/src/services/plot_data_builder.rs:229) belongs here. RN owns its own chart presentation over the same product facts.
- **Image renderer** draws the supplied viewmodel and returns image bytes. It owns graphics-library details, with no repositories, goal resolution, or scoring. Its interface can belong to disposable plot presentation; product code needs no renderer port.

Dependency direction: image HTTP composition → plot presentation → public product queries → domain; concrete graphics implements the presentation-owned renderer interface. RN transport consumes public product queries independently. Bootstrap wires optional image support. Same-process modules or an optional package/feature suffice; neither a microservice nor a general graphics grammar is justified.

Preserve `/statistics/{id}/plot/image` and `/plots/timeline/{date}`, which Obsidian requests in [refreshableImage.js](/home/daniel/main/obsidian/scripts/refreshableImage.js:38) and [showTimeline.js](/home/daniel/main/obsidian/scripts/showTimeline.js:13), including current parameters, defaults, and PNG behavior while retained. Keep `/statistics/{id}/plot/data` compatible as a presentation endpoint: its [DTO includes RGB, plot type, and axes](/home/daniel/.local/share/src/lifestats/core/infrastructure/web_api/src/routes/plots.rs:47), so it is not automatically the future RN contract.

Removal criterion: once Obsidian, wallpaper, and any other retained image consumers migrate or are explicitly retired, delete image routes, plot viewmodels, renderer interfaces/implementations, and graphics dependencies together. Product queries and native charts should require no semantic changes.
